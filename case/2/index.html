非程序员 Uber 司机让 Grok Bot 建了自己的接单数据库：1.1 万张报价截图可自然语言查询

把平台报价截图和收入导出喂给 Grok Bot 建库去重配对，普通司机也能用大白话查哪个时段、哪类单真正赚钱。
任务背景
作者 Levi 是纽约中部的 Uber 司机、不会编程。平台算法什么都知道，他却对报价规律一无所知：他想把接过和拒过的报价截图与实际收入记录配到一起，弄清哪些单跑完比看上去值、哪些不值。
做法步骤 (6 步)
  1. 1. 用 GigU 自动截下每一张 Uber 报价卡（接单拒单都截），记录票价、接驾时间距离、行程时间距离、乘客评分等
  2. 2. 从 drivers.uber.com 按周导出收入与行程数据，并向 Uber 索取自 2020 年 2 月开车以来的历史个人数据
  3. 3. 把截图和数据交给 Grok Bot，说明目标：建报价与完成行程的数据库、识别重复记录、在信息足够可靠时把报价与实际行程配对
  4. 4. 告诉它自己的口径：车辆成本约每英里 30 美分、看重落点（别把自己扔到要空驶 30 英里回来的地方）
  5. 5. 建成后用自然语言提问，如哪些时段扣掉车辆成本后收入最高、哪类行程最容易拿到小费、今晚 GigU 的每英里/每小时/评分门槛怎么设
  6. 6. 设 Grok Bot 定时例行：检查新截图入库存、找新的完成行程记录，持续更新
关键提示词 (Prompt)
PROMPT TEMPLATE
I drive Uber in [your market]. I want to build a database that helps me make better decisions about which trips to accept, when to drive, and where to drive.
产出与证据
数据库现状（原文给出具体规模）：约 11,722 张报价截图、6,909 条较新的行程记录、2,157 条报价已与完成行程成功配对，另有覆盖 13,384 趟行程、约 300 周汇总的历史数据；作者现在出车前先问库里该时段该区域的建议再去更新 GigU 设置。
复现要点
需要 Grok Bot 账号；数据侧只需 GigU 截图（2026 年内免费）加 Uber 官方导出，不需要会写代码；作者建议先攒几周报价再开建，几个月后门槛设置才有统计意义。
踩坑提示
原文提醒：截图和行程数据含敏感信息，只给 agent 限定文件夹、绝不给密码/银行截图/验证码；agent 会看错截图、配错记录或样本太小时下结论，重要结论要问样本量并回原始数据核对；别把营业额当利润，要扣车辆成本、等待和空驶。
