16 个 Grok Bot 编排编程 agent 一周合并 78 个 PR，又因烧钱停用

学会用 webhook+例行把编程线程的盯梢工作交给 Bot 团队：作者一周合并 PR 数从历史最佳 35 个涨到 78 个，也学到了成本失控的边界。
任务背景
作者写代码用 T3 Code（并排跑 Claude Code 与 Codex 线程），真正磨人的是编程之外的事：哪些 PR 在等评审、昨晚跑完了什么、接下来做什么。他想把这份心智负担交给一支常驻 Bot 团队。
做法步骤 (5 步)
  1. 1. 在 Grok Bot 里按工作领域建 16 个 Bot（Inbox、GitHub、Bugs、Blog、Research 等），另设 Config Bot 专门配置其他 Bot、Vault Bot 独占笔记写入权
  2. 2. 项目需要多人协作时把相关 Bot 拉进群聊，声明本群只做这个项目
  3. 3. 本地写一个无 AI 的小脚本：编程线程完成/失败/需要人时 ping GrokBot 的 webhook，唤醒 T3 Code Bot 来通知或反向操作，避免把本机经公网隧道暴露
  4. 4. 设两条例行扛主力：GitHub Bot 盯 PR，评审一通过就通知对应编程线程去落地（它自己从不合并，有个 PR 在通过后 2 分钟就落地）
  5. 5. 每个工作日三次，Inbox/日历/日志 Bot 汇总所见，Vault Bot 整理成排好序的优先级看板
产出与证据
一周内作者与 Bot 团队配合合并了 78 个 pull request（其历史最佳是 35 个）；优先级看板落在文档应用里随时可查，原文配有 10 月 9 日当天 24 个编程线程的通知送达情况图（17 个准时、3 个迟到、4 个从没通知）。
复现要点
需要 Grok Bot 付费套餐（作者当时已升到 200 美元档）加自己的编程 agent 工具；关键技巧是事件走 webhook 唤醒、不要用定时轮询，且先给事件加一层普通代码过滤器再唤醒 Bot。
踩坑提示
原文重点踩坑：周末无人时通知器每个事件都唤醒 Bot、Bot 思考后决定没什么可说的，一周末烧掉 100 美元并撞停支出上限、所有例行和 webhook 随之失效；设计好的过滤器（可砍约 80% 流量）Bot 建好了却没人启用，事件继续每天唤醒 Bot 500–750 次；云电脑闲置会休眠，定时任务迟到 12–80 分钟；10 月 9 日 24 个线程完成只通知了 20 个。作者最终停用整套系统。
